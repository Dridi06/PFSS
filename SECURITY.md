# Security Policy

## Supported development line

Security fixes are developed on `feature/pfss-complete-platform-build` first and are not considered deployed until the staging and production release gates have been completed.

## Reporting a vulnerability

Please do not publish credentials, access tokens, personal data, exploit details, or an unpatched vulnerability in a public issue or pull request.

Use GitHub's private vulnerability reporting / Security Advisory workflow for this repository if it is enabled. If private reporting is unavailable, contact the repository owner through the GitHub profile at https://github.com/Dridi06 and share only the minimum information needed to establish a secure follow-up.

Do not send passwords, service-role keys, database dumps, or production user data.

## Scope and response

Reports should include the affected component, impact, a minimal reproduction where safe, and whether the issue affects development, staging, or production. Do not test against systems or accounts you do not own or have explicit permission to assess.

The project will assess reports in good faith. No response-time or remediation-time SLA is currently promised.
